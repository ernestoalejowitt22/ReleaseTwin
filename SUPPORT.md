# Support

ReleaseTwin is solo-maintained. There's one path in for each kind of request.

## Where to go

| Your request | Where | Notes |
|---|---|---|
| **Bug** — wrong output, a crash, something not working | [New bug report](https://github.com/ernestoalejowitt22/ReleaseTwin/issues/new?template=bug_report.yml) | Public issue. Use the form. |
| **Feature / design idea** | [New feature request](https://github.com/ernestoalejowitt22/ReleaseTwin/issues/new?template=feature_request.yml) | Public issue. Open one before a large PR. |
| **Security** — a wrong verdict you can trigger, or a way to leak fixture content, a secret, or un-redacted evidence | [Report a vulnerability](https://github.com/ernestoalejowitt22/ReleaseTwin/security/advisories/new) | **Private.** Never a public issue. See [`SECURITY.md`](SECURITY.md). |
| **Account, billing, or legal** — something tied to your org, an invoice, a Terms/Privacy question | `support@releasetwin.com` | Email, so it can reference your account privately. |
| **Sales / pilot** — the hosted platform for your team, a design-partner engagement | `support@releasetwin.com`, subject `ReleaseTwin pilot` | |
| **Usage question** — "is this the right tool", "how do I…" | a bug/feature issue is fine, or `support@releasetwin.com` | No dedicated forum yet. |

## The support address

**`support@releasetwin.com`** — an alias on the project's mailbox. `security@`
and `legal@` reach the same inbox for those specific topics. The GitHub
issue-template contact links point here.

## What to expect

This is a solo project. Expect an acknowledgement **within about 3 business
days** and a candid answer or timeline — not a formal SLA. Paid tiers get
faster best-effort turnaround; nothing here is contractual unless it's written
into a signed agreement.

Operator triage process: [`docs/support.md`](docs/support.md).
