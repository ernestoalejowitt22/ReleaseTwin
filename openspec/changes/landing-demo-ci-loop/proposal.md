## Why

The landing page shows a terminal recording and a hand-built three-row fake table. The
product's actual payoff — a `ReleaseTwin` check that blocks a merge, a readable PR
comment, and redacted evidence landing on a deep dashboard — is invisible to visitors,
even though the CI PR integration (`integrations/github-action/`) already produces all of
it. A visitor leaves thinking "CLI tool" instead of "merge gate with a verdict you can
read and evidence you don't have to exfiltrate."

## What Changes

- Wire the ReleaseTwin GitHub Action into the **NAHA repo** (`ernestoalejowitt22/NAHA`):
  add case files + fixtures targeting NAHA's own API, and a workflow step using
  `integrations/github-action`. Land one PR that fails the gate, then a fix that passes —
  the source material for the demo screenshots.
- Add a **reproducible capture script** (same pattern as `web/scripts` / `demo:naha-video`)
  that regenerates the demo assets: the GitHub PR views (check ✗ Required, the rendered
  comment, check ✓ after the fix) and the deep dashboard views (run-history row →
  evidence viewer with auth headers stripped → trend analytics → release-readiness
  rollup), driven by the existing e2e harness.
- Replace the landing page's fake `DashboardPreview` with a **CI-loop demo section**: four
  panels (the gate / merge unblocked / the dashboard, deep / under the hood), each panel
  captioned with the claim it proves. The existing animated terminal SVG is kept but
  demoted to the "under the hood" strip.
- Add a static **Bitbucket Pipelines YAML snippet** to `docs/ci` (or the demo section)
  plus a line that the `--summary-json` contract is CI-agnostic. No Bitbucket screenshot,
  no Bitbucket Pipe — deferred.

## Capabilities

### New Capabilities
- `landing-demo`: the landing page's CI→dashboard demo is generated from real captured
  artifacts of an actual pipeline run (GitHub PR check + comment, dashboard screenshots),
  regenerated by a committed script rather than hand-authored mock data, so it cannot
  drift from the real `render.mjs` output or the real dashboard UI.

### Modified Capabilities
- `marketing-site`: the landing page SHALL present the merge-gate → PR-comment →
  dashboard-evidence loop as its primary product demo, replacing the page-local fake
  run-history table.

## Impact

- **web/**: `src/app/(marketing)/page.tsx` (remove `DashboardPreview`, add the demo
  section), `web/public/` (new captured image assets), `web/scripts/` (new capture
  script), `web/src/app/(marketing)/docs/ci/` (Bitbucket snippet). Verification:
  `npm run build` + `npx eslint`.
- **NAHA repo** (separate, private): new ReleaseTwin case + fixture files, a new
  `.github/workflows` step, one demo PR. Needs the RT CLI container image pullable from
  GHCR in NAHA's CI.
- **Credentials**: the capture script reuses the LaunchDarkly + NAHA e2e credentials the
  video demo already uses (AWS Secrets Manager / `cypress.env.json`).
- No hosted API, ingest contract, or CLI behavior changes.
