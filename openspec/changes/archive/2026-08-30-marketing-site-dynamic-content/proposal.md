## Why

The marketing site's pricing and feature content is hand-maintained prose that has already
drifted from the product:

- `web/src/app/(marketing)/pricing/page.tsx` hardcodes a `PLANS` array and a `ROWS`
  comparison table with three tiers, prices, and per-tier feature strings — none of it
  connected to what the backend actually enforces (see change
  `plan-catalog-and-entitlements`, which lands `hosted/plans.json` + `web/src/lib/plans.ts`).
- There is **no `/features` page**. The capability list lives scattered across the
  homepage, `README.md`, and the docs, and nothing states which tier each capability
  needs.
- When an entitlement changes (a new tier, a moved feature, a firmed-up price), someone
  has to remember to edit marketing copy by hand.

This change makes the plan and feature surfaces render from a single source, so the
pricing page, a new features page, and the homepage cannot disagree with the catalog.

## What Changes

- **Pricing page** (`pricing/page.tsx`) — delete the local `PLANS` / `ROWS` literals.
  Render the tier cards and the comparison table from `plans.ts` (the typed loader over
  `hosted/plans.json`). The "early-access placeholder" caveat renders automatically for
  any tier whose price is `placeholder: true`. Founding Setup and the continuity blurb
  stay as authored prose.

- **New `/features` page** (`web/src/app/(marketing)/features/page.tsx`) — one page listing
  every capability, split into:
  - **Open-source engine** — runs in your infra, no account, free (from a small authored
    list with links to the relevant docs page; these are not entitlements, they're always
    available).
  - **Hosted dashboard** — a table generated by walking the catalog's entitlement keys,
    each row showing the capability, a one-line description, and the lowest tier that
    includes it. A `FEATURE_COPY` map in `web/src/lib/plans.ts` supplies the human label
    and description for each entitlement key; a build-time check fails if the catalog has
    an entitlement key with no copy entry (or vice versa), so a new entitlement can't ship
    without a description.

- **Homepage** (`(marketing)/page.tsx`) — the feature/benefit section that currently
  inlines capability bullets pulls its "hosted adds…" items from the same `FEATURE_COPY`
  source (a curated subset, ordered by an explicit `HOMEPAGE_FEATURES` id list — not the
  whole table).

- **Footer / nav** — add `/features` to the header nav and `web/src/app/sitemap.ts`.

- **`web/src/lib/plans.ts`** (created by `plan-catalog-and-entitlements`, extended here) —
  gains `FEATURE_COPY`, `HOMEPAGE_FEATURES`, and helper selectors (`tiersForDisplay()`,
  `lowestTierWith(entitlement)`).

## Capabilities

### Added Capabilities

- `marketing-site`: the public pricing and features pages render tier and entitlement
  content from the shared plan catalog, not from page-local copy; every catalog
  entitlement has display copy, enforced at build time.

## Impact

- `web/src/app/(marketing)/pricing/page.tsx` — rewritten to consume `plans.ts`.
- `web/src/app/(marketing)/features/page.tsx` — new.
- `web/src/app/(marketing)/page.tsx` — feature section sourced from `FEATURE_COPY`.
- `web/src/lib/plans.ts` — `FEATURE_COPY`, `HOMEPAGE_FEATURES`, selectors, the
  catalog↔copy completeness check.
- `web/src/components/site-header.tsx`, `web/src/app/sitemap.ts` — add `/features`.
- `web/` tests — a rendering test that the pricing table row count matches the catalog;
  the copy-completeness check.
- **Depends on** `plan-catalog-and-entitlements` (needs `hosted/plans.json` +
  `plans.ts`). No backend change in this change.

## Open Questions

- Does the OSS-engine list on `/features` also come from a data file, or stay authored
  prose? Proposed: **authored prose** — it's a stable, small list that maps to docs
  pages, not entitlements; over-engineering it adds nothing.
- `/features` vs folding it into the existing `/pricing` comparison table. Proposed:
  **separate page** — pricing answers "what does it cost", features answers "what can it
  do"; the homepage links both. Keeps each page short.
- Price display when `placeholder: true` and `amount` is set: show the number with the
  caveat (proposed) vs hide the number until GA. Proposed: **show it** — a soft anchor is
  more useful to an evaluator than "contact us", and the caveat is already the site's
  established tone.
