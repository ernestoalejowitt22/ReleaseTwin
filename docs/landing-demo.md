# Landing-page CI-loop demo — regenerating the assets

Internal reference. The landing page's product demo shows one real loop: a NAHA pull
request fails the `ReleaseTwin` gate → a fix turns it green → the redacted evidence lands
on the hosted dashboard. Every panel is a captured artifact of a real run, regenerated by
the steps here — never hand-authored mock data (see
`openspec/changes/landing-demo-ci-loop/specs/landing-demo/spec.md`).

## Assets the landing page consumes

| File (in `web/public/`) | Panel | Source |
|---|---|---|
| `demo/pr-gate-fail.png` | ① merge blocked | the NAHA demo PR with `DEMO-GATE-1` red, merge box showing "Required" |
| `demo/pr-comment.png` | ② readable verdict | the `ReleaseTwin` PR comment rendered by `integrations/github-action/render.mjs` |
| `demo/pr-gate-pass.png` | ② unblocked | same PR after the fix commit, check green |
| `demo/dashboard-runs.png` | ③ dashboard | hosted dashboard run history |
| `demo/dashboard-evidence.png` | ③ dashboard | evidence viewer, auth headers stripped |
| `demo/dashboard-trends.png` | ③ dashboard | trend analytics |
| `demo/dashboard-rollup.png` | ③ dashboard | release-readiness rollup |

## Prerequisites

1. CLI image published — `v0.1.0` tag on ReleaseTwin, package public or NAHA granted
   access (see `openspec/changes/landing-demo-ci-loop/preflight.md`).
2. NAHA repo secrets set: `RELEASETWIN_NAHA_API_URL`, `RELEASETWIN_NAHA_E2E_SECRET`,
   `RELEASETWIN_NAHA_ADMIN_EMAIL` (from AWS `releasetwin/e2e/naha-account`).
3. The NAHA `releasetwin-gate` branch merged, so the workflow is on `main`.
4. Local AWS session that can read `releasetwin/e2e/naha-account` and
   `releasetwin/e2e/launchdarkly-account` (IAM user `releasetwin-e2e-secrets-reader`).

## Step 1 — the demo PR (in the NAHA repo)

Follow `releasetwin/README.md` in NAHA: open a PR that adds `releasetwin/cases/demo-gate.yaml`
(`DEMO-GATE-1`, asserting `$.principal.role == superadmin` — wrong on purpose). The
`ReleaseTwin` check goes red.

- Screenshot the PR's merge box (check ✗, "Required" if the branch protection is set) → `pr-gate-fail.png`.
- Screenshot the rendered `ReleaseTwin` comment → `pr-comment.png`.

Push the fix commit (`superadmin` → `admin`). The check goes green, the comment updates in
place.

- Screenshot the merge box (check ✓, merge enabled) → `pr-gate-pass.png`.

Both cases are verified to behave as designed against the live NAHA e2e API
(`NAHA-ADMIN-AUTH-1` PASS exit 0, `DEMO-GATE-1` FAIL exit 1).

## Step 2 — the dashboard panels

The evidence from the NAHA run must reach the hosted dashboard (project connected with
`RELEASETWIN_API_TOKEN` + evidence upload opt-in for that project). Then drive the existing
Cypress dashboard walkthrough with screenshot capture:

```bash
cd web
CYPRESS_VIDEO=false npm run e2e -- --spec cypress/e2e/dashboard-walkthrough.cy.ts
```

Collect the run-history, evidence-viewer, trends, and rollup screenshots from
`web/cypress/screenshots/` and copy them into `web/public/demo/` under the names above.
Crop/normalize to a consistent width.

## Step 3 — wire into the landing page

`web/src/app/(marketing)/page.tsx` — replace `DashboardPreview` with the four-panel demo
section, each panel captioned with the claim it proves. Keep `demo-flag-proof.svg` as the
"under the hood" strip. Use `next/image` with explicit dimensions; lazy-load below the fold.

## Review checklist — before committing any asset

- [ ] Every value visible is test data (NAHA e2e account, seeded fixtures) — no real
      customer, operator, or production content.
- [ ] No credential-shaped strings visible (bearer tokens, `x-e2e-secret`, API keys) in
      any screenshot — the evidence viewer strips these, but raw screen capture does not.
- [ ] The PR author/branch names are the demo ones, nothing sensitive.
- [ ] Image file sizes are reasonable for a landing page (compress PNGs).
